# Словарь терминов проекта (Glossary)

> **Назначение:** Универсальный язык (ubiquitous language) для общения между разработчиком и AI-агентом. Все термины здесь — это те слова, которые мы используем одинаково в коде, в чате и в документации.
>
> **Обновляется:** интерактивно через `/grill-with-docs` и `/domain-modeling`.

---

## Основные сущности

| Термин | Описание |
|--------|----------|
| **User (Пользователь)** | Telegram-пользователь, взаимодействующий с ботом. |
| **Person (Персона)** | Профиль человека (имя, возрастная категория). Связан с `User`. Может быть `Adult` (Взрослый) или `Child` (Ребенок). |
| **TheaterEvent (Мероприятие)** | Описание спектакля или программы (название, возрастные ограничения, длительность). |
| **ScheduleEvent (Сеанс)** | Конкретный сеанс спектакля в расписании (дата, время, доступные места). |
| **BaseTicket (Шаблон билета)** | Определяет формат посещения (например, "1 взр + 1 реб") и стоимость. |
| **Ticket (Билет)** | Запись о бронировании конкретным пользователем на конкретный сеанс. |
| **ScheduleChange (Журнал изменений)** | Запись об атомарном создании или изменении сеанса (автор, источник, операция, снимки `before`/`after`, статус Telegram-отчёта и статус выгрузки в Google Sheets). |
| **ScheduleSyncRun (Запуск выгрузки)** | Запись об управляемом запуске выгрузки накопленных изменений расписания в Google Таблицу (UUID, инициатор, срез изменений, результаты по сеансам, статус доставки сводки). |

## Статусы билетов (`TicketStatus`)

| Термин | Описание |
|--------|----------|
| **CREATED** | Бронирование создано, ожидается оплата. |
| **PAID** | Оплата подтверждена платежной системой. |
| **APPROVED** | Подтверждено администратором или системой (места зафиксированы). |
| **REJECTED / CANCELED** | Отменено. |
| **REFUNDED** | Оформлен возврат. |

## Telegram-бот и python-telegram-bot

| Термин | Описание |
|--------|----------|
| **ConversationHandler** | Механизм `python-telegram-bot` для управления состоянием диалога с пользователем. Состояния определяются в `src\conv_hl\`, бизнес-логика — в `src\handlers\`. |
| **Handler (Обработчик)** | Функция, реагирующая на команду, callback или текст пользователя. Регистрация централизована в `src\setup_bot_handlers.py`. |
| **Inline Keyboard** | Клавиатура с кнопками под сообщением бота. Создаётся через `src\utilities\utl_kbd.py`. |
| **Middleware** | Промежуточный обработчик, выполняющийся до/после handler'а. Стартовые middleware: `add_db_handlers_middleware`, `add_user_status_middleware`, `add_command_permission_middleware`, `add_glob_on_off_middleware`, `add_reserve_check_middleware`, `add_tg_update_logging_middleware`. |
| **Custom Filter** | Пользовательский фильтр для маршрутизации обновлений (например, `REPLY_IN_TOPIC_FROM_BOT` для реплик в топиках). |
| **Command Permission** | Система прав на команды: `can()` проверяет гранты в `user_command_access`, middleware `command_permission` блокирует доступ по `can()`, UI «Доступ к командам» в `/settings` → «База данных» позволяет управлять грантами. Middleware `glob_usage_users` и `reserve_check` также используют только `can()`. |

## NATS и FastStream

| Термин | Описание |
|--------|----------|
| **NATS** | Брокер сообщений для связи между FastAPI, Telegram-ботом и фоновыми воркерами. |
| **FastStream** | Фреймворк для работы с NATS в Python, используется для подписок и публикации. |
| **JetStream** | Персистентный слой NATS с именем `baby_domik` (max_msgs=100, max_age=7 days). |
| **Тема (Subject)** | Канал обмена сообщениями: `yookassa`, `gspread`, `gspread_failed`, `schedule_sync_result`, `sales`, `sales_report`. |
| **Durable Consumer** | Подписка NATS, сохраняющая состояние между перезапусками. |
| **Publisher (Издатель)** | Компонент, публикующий сообщения: FastAPI (вебхуки YooKassa), Gspread Pub, Sales Pub. |
| **Worker (Воркер)** | Фоновый процесс, подписанный на тему: Gspread Worker (запись в Google Sheets), Sales Worker (рассылки). |

## Авторассылки (Auto-sendings)

| Термин | Описание |
|--------|----------|
| **AutoSending (Рассылка)** | Запись о шаблоне автоматической рассылки: название, триггер (`EVENT`/`PAYMENT`), смещение в минутах от сеанса, окно отправки, текст в HTML, флаг точности (`precise`). |
| **AutoSendingDelivery (Журнал доставки)** | Запись об успешной доставке рассылки пользователю: `auto_sending_id`, `user_id`, `dedup_key`, `sent_at`. UNIQUE индекс гарантирует отсутствие дублей. |
| **AutoSendingTrigger** | Перечисление типов триггеров: `EVENT` (по расписанию, через тик) и `PAYMENT` (после оплаты, через webhook). |
| **Tick (Тик)** | Периодический запуск `auto_sending_tick` каждые 3 минуты (180 сек) для обработки EVENT-рассылок. |
| **Catch-up window (Окно догона)** | Интервал, равный периоду тика (3 мин), в котором тик подхватывает пропущенные рассылки после перезапуска бота. |
| **Precise mode (Точный режим)** | Режим рассылки, где тик планирует `run_once` задачу на точное время отправки вместо немедленной отправки. |
| **Recipient Selector (Селектор получателей)** | Функция, которая по рассылке и текущему времени возвращает список получателей с контекстом для рендеринга текста. |
| **Dedup key (Ключ дедупликации)** | Уникальный идентификатор отправки в формате `se:{schedule_event_id}`, используется для проверки «уже отправлено ли» через журнал. |

## Фискальные чеки (Receipts)

| Термин | Описание |
|--------|----------|
| **ReceiptStatus** | Статус фискального чека (StrEnum): `READY` (чек сформирован), `PENDING` (оплата ожидается), `CANCELED` (платеж отменён), `NO_PAYMENT` (платёж не найден по билету), `NOT_FOUND` (билет не найден), `API_ERROR` (ошибка YooKassa API). |
| **ReceiptInfo** | Данные чека (dataclass): статус, фискальные данные (FN, FP, номер чека, дата, сумма), публичная ссылка OFD, `client_chat_id` для отправки клиенту. |
| **get_ticket_receipt** | Функция (`src/api/receipt_service.py`) — получает статус и данные чека по ID билета: находит платеж, вызывает YooKassa SDK, маппит статус платежа на `ReceiptStatus`. |
| **fetch_payment_receipts** | Асинхронная обёртка (`src/api/yookassa_connect.py`) — вызывает `Receipt.list` через `asyncio.to_thread` + `wait_for(10s)` для получения чеков по ID платежа. |
| **build_ofd_url** | Функция (`src/api/yookassa_connect.py`) — формирует публичную ссылку OFD по фискальным номерам (FN, FP, номер чека). |
| **Команда /receipt** | Админская команда — отправляет карточку чека с фискальными данными, кнопкой OFD-ссылки и кнопкой «📤 Отправить клиенту». |
| **Кнопка «🧾 Чек»** | Inline-кнопка в уведомлении о платеже (webhook), сохраняется после confirm/reject, открывает карточку чека. |
| **Отправка клиенту** | Кнопка «📤 Отправить клиенту» в карточке чека — отправляет ссылку на чек в чат клиента; при `Forbidden` сообщает «Клиент заблокировал бота». |
