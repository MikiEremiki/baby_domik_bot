# Prototype

Прототип — это **одноразовый код, который отвечает на вопрос**. Вопрос определяет форму.

## Выбери ветку

Определи, какой вопрос задаётся, из промпта пользователя, окружающего кода или спросив пользователя:

- **"Правильно ли работает эта логика / модель состояния?"** → Логика. Создай один HTML-файл с кнопками для свободного выбора и пошаговыми сценариями, которые проталкивают машину состояний через случаи, сложные для рассуждений на бумаге.
- **"Как это должно выглядеть?"** → UI. Сгенерируй несколько радикально разных вариантов UI на одном маршруте, переключаемых через параметр URL и плавающую панель внизу.

Две ветки производят очень разные артефакты, поэтому ошибка здесь портит весь прототип. Если вопрос действительно неоднозначен и пользователь недоступен, выбери ветку, которая лучше соответствует окружающему коду (бэкенд-модуль → логика; страница или компонент → UI) и укажи предположение вверху прототипа.

## Правила для обеих веток

1. **Одноразовый с первого дня, и явно помечен как таковой.** Размести код прототипа рядом с тем местом, где он действительно будет использоваться (рядом с модулем или страницей, для которой прототипируется), чтобы контекст был очевиден, но назови его так, чтобы случайный читатель видел, что это прототип, не продакшн. Для UI-прототипов используй уже существующее соглашение о маршрутизации проекта; не изобретай новую структуру.
2. **Тривиально запустить.** UI-прототип запускается одной командой: `python <path>`, `node <path>`, и т.д. Логическая демо — один HTML-файл, который пользователь открывает двойным кликом. В любом случае, думать не нужно.
3. **Нет персистентности по умолчанию.** Состояние живёт в памяти. Персистентность — это то, что прототип **проверяет**, не то, от чего он зависит. Если вопрос явно включает базу данных, используй временную БД или локальный файл с явным именем "PROTOTYPE, wipe me".
4. **Пропусти полировку.** Нет тестов, нет обработки ошибок сверх того, что делает прототип **запускаемым**, нет абстракций. Цель — быстро узнать что-то.
5. **Покажи состояние.** После каждого действия (логика) или при каждом переключении варианта (UI) выведи или отрисуй полное релевантное состояние, чтобы пользователь видел, что изменилось.
6. **Зафиксируй, когда готов.** Встрой любое валидированное решение в реальный код, затем сохрани сам прототип как **первичный источник**: закоммить на временную ветку, вне main, и оставь ссылку на эту ветку в тикете реализации. Зафиксируй ответ (вердикт и вопрос, который он разрешил) в тикете или коммите. Main ветка хранит только валидированное решение.

## UI прототип

Для UI-прототипа в вашем проекте (No-Build SPA):

- Создай HTML-файл рядом с прототипируемой страницей, например `web/static/prototype-<feature>.html`
- Используй существующие CSS-переменные и стили проекта для консистентности
- Сгенерируй **3-4 радикально разных варианта**, переключаемых через `?variant=1` / `?variant=2` / `?variant=3`
- Добавь плавающую панель внизу для переключения вариантов
- Каждый вариант должен быть самодостаточным: не ломай текущее поведение приложения

## Логический прототип

Для логического прототипа:

- Создай один HTML-файл с `<style>` и `<script>` внутри
- Кнопки для каждого действия или перехода состояния
- Таблица или список для отображения текущего состояния после каждого действия
- Пошаговые сценарии для сложных случаев, которые трудно рассуждать на бумаге
