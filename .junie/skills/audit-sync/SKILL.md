# Audit Sync

Проверка актуальности всех отчётов аудитов в `.junie/audit/reports/`. Сравнивает каждую проблему из отчётов с текущим состоянием кода и находит конфликты.

## Как это работает

1. Пользователь вызывает `/audit-sync`
2. Агент читает все отчёты из `reports/` (игнорируя README.md)
3. Для каждой проблемы из каждого отчёта проверяет:
   - **Файл существует** — не удалён ли файл
   - **Строки актуальны** — не сместились ли строки из-за изменений
   - **Код на месте** — не переехал ли код в другой файл
   - **Сигнатура функции** — не изменилась ли сигнатура
   - **Архитектура** — не изменилась ли структура модуля
4. Создаёт отчёт проверки `reports/YYYY-MM-DD_sync-check.md`
5. Обновляет отчёты с простыми конфликтами автоматически
6. Для сложных конфликтов — предлагает варианты решений

## Когда использовать

- Пользователь хочет проверить, актуальны ли отчёты аудитов
- После крупного рефакторинга или серии задач
- Перед созданием плана устранения из отчётов
- Пользователь явно вызывает `/audit-sync`

## Типы конфликтов

| Тип | Описание | Пример |
|-----|----------|--------|
| **Строки сместились** | Код тот же, но строки изменились | `engine.py:123` → `engine.py:145` |
| **Файл удалён** | Файл больше не существует | `old_module.py` удалён |
| **Код переехал** | Логика перенесена в другой файл | `engine.py:parse()` → `parser.py:parse()` |
| **Сигнатура изменилась** | Функция та же, но параметры другие | `calc(x)` → `calc(x, y, z)` |
| **Архитектура изменилась** | Структура модуля/класса переделана | Метод разбит на 3 метода |
| **Проблема исправлена** | Код больше не содержит проблему | DRY-нарушение устранено |
| **Актуально** | Проблема всё ещё существует без изменений | — |

## Процесс выполнения

**1. Соберите все отчёты**
- Прочитайте все файлы из `.junie/audit/reports/` кроме `README.md`
- Для каждого отчёта извлеките все проблемы из секции "Найденные проблемы"

**2. Проверьте каждую проблему**
- Откройте файл, указанный в проблеме
- Найдите код по номеру строки (±10 строк для учёта смещения)
- Определите тип конфликта:

| Сценарий | Тип конфликта | Действие |
|----------|---------------|----------|
| Код найден на тех же строках | Актуально | Ничего не делать |
| Код найден на других строках | Строки сместились | Автообновить |
| Файл не найден | Файл удалён | Спросить пользователя |
| Код не найден в файле, но найден в другом | Код переехал | Спросить пользователя |
| Функция найдена, сигнатура другая | Сигнатура изменилась | Автообновить |
| Метод разбит/объединён | Архитектура изменилась | Спросить пользователя |
| Проблема больше не воспроизводится | Проблема исправлена | Автообновить |

**3. Обновите отчёты с простыми конфликтами**
- **Строки сместились:** обновите номер строки в отчёте
- **Сигнатура изменилась:** обновите описание в отчёте
- **Проблема исправлена:** отметите проблему как `[x] Исправлено` с датой

**4. Для сложных конфликтов — предложите варианты**
- **Файл удалён:** "Файл `old_module.py` удалён. Что делать? (1) Удалить проблему из отчёта (2) Код переехал в `new_module.py` — обновить"
- **Код переехал:** "Логика из `engine.py:parse()` перенесена в `parser.py:parse()`. Обновить отчёт?"
- **Архитектура изменилась:** "Метод `calculate()` разбит на 3 метода. Проблема больше не актуальна в прежнем виде. (1) Удалить из отчёта (2) Обновить описание (3) Запустить новый аудит"

**5. Создайте отчёт проверки**
- **Путь:** `.junie/audit/reports/YYYY-MM-DD_sync-check.md`
- **Шаблон:** см. ниже

## Обновление статистики

После проверки обновите `.junie/audit/STATISTICS.md`:

- **Общая сводка:** Обновите счётчик "Исправлено" на основе найденных исправленных проблем
- **По частоте проблем:** Уменьшите счётчик для исправленных проблем
- **По файлам (top-10):** Обновите если файлы удалены или переименованы
- **Добавьте секцию "Синхронизация":** дату последней проверки, количество проверенных проблем

## Примеры использования

### Базовая проверка

Пользователь: `/audit-sync`

Результат: Проверка всех отчётов, автообновление простых конфликтов, отчёт с деталями.

### Проверка после рефакторинга

Пользователь: `/audit-sync` (после серии задач по рефакторингу)

Результат: Отчёт покажет, какие проблемы исправлены рефакторингом, а какие требуют внимания.

### Перед созданием плана

Пользователь: `/audit-sync` → "Создай план устранения из актуальных проблем"

Результат: Сначала синхронизация, затем план из только актуальных проблем.
