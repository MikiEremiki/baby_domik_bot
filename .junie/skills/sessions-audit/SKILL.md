# Sessions Audit

Количественный аудит журналов Junie (`~\.junie\sessions`) с выводами о выборе моделей. Скрипты в `scripts/` — проверенный пайплайн из аудита 2026-10-06; опорные цифры для сравнения — в `reference/baseline-2026-10-06.md`.

## Когда использовать

- «Проанализируй мои сессии Junie / с какими моделями я работаю»
- «Какие модели справились бы лучше с моими задачами»
- «Повтори аудит и сравни с прошлым»

Рекомендуемая модель для самого аудита: sonnet/opus. junie-lite в прошлый раз ошиблась в подсчётах (см. «Ловушки»).

## Структура данных

| Путь | Что внутри |
|---|---|
| `index.jsonl` | Каталог: `sessionId`, `projectDir`, `taskName`, `status`. **Одна сессия записана много раз** — дедуплицируйте по `sessionId`. |
| `<session>\events.jsonl` | Журнал событий (до сотен МБ — не читать целиком, только скриптами). |
| `<session>\transcript.md` | В старых сессиях есть только он — данных о шагах и стоимости нет. |

Ключевые события в `events.jsonl`:
- `UserPromptEvent` — промпт; `customAttachments[kind=ModelForLaunchAttachment].modelId` — **модель, выбранная пользователем**, `EffortForLaunchAttachment.effort` — effort.
- `SessionModelEffortSetEvent.modelId` — модель сессии (запасной вариант).
- `SessionA2uxEvent.event.agentEvent`:
  - `LlmResponseMetadataEvent` — `agent.kind` (`MainAgent` / субагент / нет = служебный вызов), `modelUsage[].model/cost/outputTokens`;
  - `AgentFailureEvent`, `AgentPatchCreatedEvent`, `SubagentSpawnedEvent`.
- `CancelAgentEvent`, `AgentTaskFailedEvent` — отмены и сбои.

## Процесс

Скрипты пишут результаты в `%TEMP%\sessions-audit` (меняется через `--out`) — не в проект. Запускать из корня проекта:

```powershell
$env:PYTHONIOENCODING='utf-8'; $S='.junie\skills\sessions-audit\scripts'
.venv\Scripts\python.exe $S\scan_sessions.py          # 1. инвентаризация: сессии, виды событий
.venv\Scripts\python.exe $S\scan_prompts.py           # 2. prompts.json + таблицы по моделям/категориям/месяцам
.venv\Scripts\python.exe $S\inspect_examples.py | Select -First 120   # 3. фактическая модель, примеры переделок
.venv\Scripts\python.exe $S\rework_by_project.py --session <текущая-сессия>  # 4. негатив по (проект, модель)
```

Затем:
1. Сверить выбранную модель (`sel`) с фактической моделью главного агента (`main_model`) — подменяется ли модель.
2. Отделить служебные модели (gpt-4.1*, gpt-5.4-nano, haiku, gemini-*-flash-lite) — пользователь их не выбирал, в распределение не включать.
3. По `inspect_examples.py` прочитать реальные тексты переделок/отмен и найти **цепочки** («опять сломалось» 3–5 промптов подряд).
4. Для спорных утверждений проверять источник точечным запросом к `prompts.json` (сколько уникальных сессий, какая модель).
5. Сравнить с `reference/baseline-2026-10-06.md`: что изменилось в распределении, стоимости, доле переделок.
6. Выдать отчёт (формат ниже). Если пользователь просит — обновить baseline новым файлом `reference/baseline-YYYY-MM-DD.md`.

## Ловушки (ошибки прошлого аудита junie-lite)

- Считать строки `index.jsonl` как сессии (334 строки = 131 уникальная сессия).
- Включать служебные модели в «ваши модели».
- Приписывать задачу модели по совпадению строки в каталоге, не проверив промпт.
- Делать выводы по 1 промпту, размноженному дубликатами каталога («HTTP 304 отлаживали 6 раз»).
- Метрика `rework`/`neg%` — по ключевым словам следующего промпта; сравнивать только внутри одного проекта, это ориентир, а не оценка качества.

## Формат отчёта

1. Методика и охват: сессий, промптов, сколько без журнала.
2. Таблица по выбранным моделям: промпты, период, шагов/промпт, $/промпт, сбои/отмены, негативный следующий промпт.
3. Оценка по моделям с примерами из журналов.
4. Таблица «тип задачи → сейчас → рекомендую → почему».
5. Сравнение с baseline: что изменилось.
6. Ограничения.

## Правила

- Не менять файлы в `~\.junie\sessions` — только чтение.
- Не класть промежуточные JSON в проект.
- Учитывать, что junie-lite бесплатна (Qwen3.6-27B-FP8), стоимость остальных моделей — из `modelUsage.cost`.
