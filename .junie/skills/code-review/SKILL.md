# Code Review

Двухосный ревью изменений с момента последней точки фиксации. Каждая ось независима, чтобы одна не загрязняла другую.

## Ось 1: Стандарты

Проверьте, следует ли код стандартам репозитория и базовым принципам качества:

- **Стиль кода:** именование, форматирование, порядок импортов, PEP 8
- **DRY:** нет дублирования логики
- **Кодовые запахи (Fowler):**
  - Long Method (> 20 строк)
  - Large Class (> 200 строк)
  - Feature Envy (метод использует больше данных другого класса)
  - Data Clumps (группы полей, всегда используемые вместе)
  - Primitive Obsession (примитивы вместо value objects)
- **Тесты:** покрыты ли критические пути
- **Документация:** обновлены ли docs/ при изменениях
- **Изоляция сервисов:** нет импорта ptb в FastAPI, нет импорта gspread в воркеры
- **Безопасность:** SQL-инъекции, XSS в Telegram-сообщениях, secrets не закоммичены

## Ось 2: Спецификация

Проверьте, faithfully ли код реализует исходную задачу:

- **Соответствие задаче:** реализовано ли то, что просили
- **Edge-кейсы:** обработаны ли граничные случаи (пустой список событий, недоступная БД, таймаут Google Sheets)
- **Регрессии:** не сломано ли существующее поведение
- **NATS контракты:** совместимы ли изменения publisher/consumer

## Процесс

1. Получите diff изменений: `git diff` или список изменённых файлов
2. **Ось 1 (Стандарты):** проверьте код по чек-листу выше
3. **Ось 2 (Спецификация):** сравните с описанием задачи
4. Сформируйте отчёт с найденными проблемами
