# Git Commits Skill

Создание веток и коммиты с правильными сообщениями.

Этот скилл охватывает только создание веток и коммиты. Слияния (merge) и пуши (push) выполняются вручную пользователем.

## Когда использовать

- Пользователь просит создать ветку (`создай ветку`, `create branch`, `checkout`)
- Пользователь просит сделать коммит (`сделай коммит`, `commit`, `закоммить`)
- Пользователь просит отменить последние изменения (`отмени merge`, `reset`, `revert`)

## Конвенции

### Ветки

- Фичи: `feature/<краткое-описание>` (например, `feature/admin-global-prices`)
- Баг-фиксы: `fix/<краткое-описание>` (например, `fix/payment-button-loading`)
- Рефакторинг: `refactor/<краткое-описание>` (например, `refactor/split-large-files`)
- Документация: `docs/<краткое-описание>`
- Имена веток на английском, kebab-case

### Коммиты

- Формат: Conventional Commits
  - `feat: <описание>` — новая фича
  - `fix: <описание>` — исправление бага
  - `refactor: <описание>` — рефакторинг без изменения поведения
  - `docs: <описание>` — изменения документации
  - `chore: <описание>` — вспомогательные задачи
- Язык сообщений: русский или английский, в зависимости от контекста
- **Обязательно** добавляйте co-author: `--trailer "Co-authored-by: Junie <junie@jetbrains.com>"`
- Коммиты должны быть атомарными — одна логическая единица работы

## Стандартные операции

### 1. Создание ветки

```powershell
git checkout main  # или develop
git checkout -b feature/<name>
```

### 2. Коммит изменений

```powershell
git add .
git commit -m "feat: <описание>" --trailer "Co-authored-by: Junie <junie@jetbrains.com>"
```

### 3. Откат случайного merge

Если пользователь случайно сделал merge (например, main в develop):

```powershell
git log --oneline -10
git reset --hard <commit-before-merge>
git status
```

Предупредить пользователя, что локальные изменения после merge будут потеряны.

### 4. Исправление commit message

```powershell
git commit --amend -m "correct message" --trailer "Co-authored-by: Junie <junie@jetbrains.com>"
```

## Правила безопасности

- **Никогда** не делайте `git push --force` без явного подтверждения пользователя
- **Никогда** не удаляйте ветки без подтверждения
- **Всегда** проверяйте `git status` перед операциями
- **Всегда** сохраняйте важные изменения перед reset/rebase
- При неопределённости — спросите пользователя

## Работа с планами

- Временные артефакты (SPEC, тикеты, PLAN) живут в `.scratch/` и удаляются с фичей.
- Долгосрочные планы в `.junie/plans/` обновляются по мере реализации.
- Коммит с обновлённым планом: `docs: update plan status for <plan-name>`
