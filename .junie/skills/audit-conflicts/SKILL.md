# Audit Conflicts

Проверка всех отчётов аудитов в `.junie/audit/reports/` на конфликты между собой. Не проверяет код — только согласованность отчётов друг с другом.

## Как это работает

1. Пользователь вызывает `/audit-conflicts`
2. Агент читает все отчёты из `reports/` (игнорируя README.md и sync-check)
3. Сравнивает все проблемы из всех отчётов по 4 критериям:
   - **Дублирование** — одна проблема в двух отчётах
   - **Противоречивые статусы** — исправлено в одном, активно в другом
   - **Конфликт исправлений** — разные решения для одного файла
   - **Пересечение областей** — один файл в разных отчётах
4. Создаёт отчёт конфликтов `reports/YYYY-MM-DD_conflicts-check.md`

## Когда использовать

- Перед созданием плана устранения из нескольких отчётов
- После добавления нового отчёта аудита
- Когда подозреваете, что проблемы дублируются
- Пользователь явно вызывает `/audit-conflicts`

## Типы конфликтов

| Тип | Описание | Пример |
|-----|----------|--------|
| **Дублирование проблем** | Одна и та же проблема (файл + строка + описание) зафиксирована в двух отчётах | SOLID аудит: `engine.py:123` — большой метод; Type Hints аудит: `engine.py:123` — тот же метод без типов |
| **Противоречивые статусы** | В одном отчёте проблема исправлена, в другом — ещё активна | SOLID: `[x] Исправлено` DRY в `engine.py`; Type Hints: `[ ] Активно` тот же файл |
| **Конфликт исправлений** | Два отчёта предлагают разные исправления для одного файла/метода | SOLID: "разбить метод на 3 части"; Frontend: "полностью переписать метод" |
| **Пересечение областей** | Два отчёта затрагивают один файл по разным причинам | SOLID: `engine.py` — DRY; Configuration: `engine.py` — магические числа |

## Процесс выполнения

**1. Соберите все отчёты**
- Прочитайте все файлы из `.junie/audit/reports/` кроме `README.md` и файлов `*-sync-check.md`
- Для каждого отчёта извлеките все проблемы из секции "Найденные проблемы"
- Для каждой проблемы сохраните: файл, строка, описание, статус (активно/исправлено), тип аудита

**2. Проверьте дублирование проблем**
- Сравните все проблемы по ключу: `файл:строка`
- Если одна и та же проблема (похожее описание) найдена в двух отчётах — отметьте как дубликат
- **Критерий дубликата:** одинаковый файл + строка в пределах ±5 строк + похожее описание

**3. Проверьте противоречивые статусы**
- Для каждой пары проблем с одинаковым `файл:строка` проверьте статусы
- Если в одном отчёте `[x] Исправлено`, а в другом `[ ] Активно` — отметьте как противоречие

**4. Проверьте конфликт исправлений**
- Для каждого файла, который встречается в нескольких отчётах, проверьте секции "Рекомендации" или "План устранения"
- Если для одного метода/функции предложены разные исправления — отметьте как конфликт

**5. Проверьте пересечение областей**
- Сгруппируйте все проблемы по файлам
- Для файлов, которые встречаются в 2+ отчётах, отметьте как пересечение
- Укажите, какие виды аудитов затрагивают файл

**6. Создайте отчёт конфликтов**
- **Путь:** `.junie/audit/reports/YYYY-MM-DD_conflicts-check.md`
- **Шаблон:** см. ниже

```markdown
# Отчёт конфликтов между аудитами

## Метаданные

## Сводка

## Дублирование проблем

Одни и те же проблемы, зафиксированные в разных отчётах:

### Дубликат 1: `src/handlers/reserve_hl.py:123`
- **Отчёт 1:** `2026-10-05_initial-solid-audit.md` — "Большой метод handle_payment(), 200+ строк"
- **Отчёт 2:** `2026-10-05_initial-type-hints-audit.md` — "Метод handle_payment() без return type hint"
- **Рекомендация:** Объединить в один пункт или оставить как разные аспекты одной проблемы

---

## Противоречивые статусы

Проблемы с разными статусами в разных отчётах:

### Противоречие 1: `src/handlers/reserve_hl.py:45`
- **Отчёт 1:** `2026-10-05_initial-solid-audit.md` — [x] Исправлено, DRY устранено
- **Отчёт 2:** `2026-10-05_initial-type-hints-audit.md` — [ ] Активно, нет type hints
- **Рекомендация:** Уточнить, исправлена ли проблема полностью или частично

---

## Конфликт исправлений

Разные предложения по исправлению одного файла/метода:

### Конфликт 1: `src/handlers/reserve_hl.py:handle_payment()`
- **Отчёт 1 (SOLID):** "Разбить метод на 3 части: validate, process, notify"
- **Отчёт 2 (Error Handling):** "Полностью переписать метод с обработкой исключений"
- **Рекомендация:** Согласовать порядок исправлений — сначала рефакторинг SOLID, потом обработка ошибок

---

## Пересечение областей

Файлы, затронутые несколькими аудитами:

| Файл | Виды аудитов | Количество проблем |
|------|-------------|-------------------|
| `src/handlers/reserve_hl.py` | SOLID, Type Hints, Configuration | 7 |
| `src/api/web/routes/booking.py` | Security, Error Handling | 4 |
| `templates/booking.html` | Frontend, DRY | 3 |

---

## Рекомендации

На основе найденных конфликтов:

1. **Приоритет исправлений:** если файл затронут несколькими аудитами, исправлять по приоритету аудита (SOLID → Type Hints → Configuration)
2. **Объединение дубликатов:** если одна проблема найдена в двух отчётах, оставить в отчёте с более высоким приоритетом
3. **Согласование статусов:** перед созданием плана устранить все противоречия
4. **Порядок работы:** при пересечении областей — исправлять файл целиком, а не по частям

## Выводы

- X дубликатов можно объединить
- Y противоречий требуют уточнения
- Z конфликтов исправлений нужно согласовать
- K файлов затронуты несколькими аудитами
```

## Обновление статистики

После проверки обновите `.junie/audit/STATISTICS.md`:
- **Добавьте секцию "Конфликты между отчётами":** дату проверки, количество каждого типа конфликта
- **Обновите "По файлам (top-10)":** если найдены файлы с пересечением областей, добавить пометку

## Примеры использования

### Базовая проверка

Пользователь: `/audit-conflicts`

Результат: Проверка всех отчётов на 4 типа конфликтов, отчёт с деталями.

### Перед созданием плана

Пользователь: `/audit-conflicts` → "Создай план устранения"

Результат: Сначала проверка конфликтов, затем план без дубликатов и противоречий.

### После нового аудита

Пользователь: `/audit solid` → `/audit-conflicts`

Результат: Новый отчёт SOLID проверен на дубликаты с существующими отчётами.
