# Ask Junie

Вы не помните каждый скилл — спросите. Junie подскажет, какой скилл использовать для вашей ситуации.

## Выбор воркфлоу

Определите размер задачи и выберите подходящий воркфлоу:

### Мгновенные правки
**1 файл, решение очевидно, нет риска сломать.**

Просто скажите Junie — без скиллов. Примеры: изменить текст кнопки, поменять цвет, исправить опечатку, добавить комментарий, переименовать переменную.

### Простой режим
**2-3 файла, решение ясно, задача однозначна.**

```
/task-check → /implement → /code-review
```

Примеры: добавить валидацию поля, поправить формулу, добавить эндпоинт, изменить структуру данных. Без grill и spec, но с проверкой DRY, edge-кейсов и ревью.

### Основной поток
**Средняя фича, задача неоднозначна, нужно уточнить.**

```
/grill-with-docs → /to-spec → /task-check → /implement → /code-review → /commits
```

1. **`/grill-with-docs`** уточняет идею через опрос, обновляет `docs/GLOSSARY.md` и ADR. (Нет рабочего каталога? Используйте `/grill-me`.)

2. **Ветка: нужно ли увидеть UI?** Если вопрос требует прототипа:
   - **`/prototype`** для 3-4 вариантов дизайна
   - Вернитесь к идее с тем, что узнали

3. **`/to-spec`** превращает обсуждение в спецификацию в `.scratch/SPEC.md`.

4. **Ветка: влезает ли работа в одну сессию?**
   - Да: переходите к `/task-check`
   - Нет: **`/to-tickets`** разбивает на тикеты

5. **`/task-check`** проверяет DRY, edge-кейсы, регрессии.

6. **`/implement`** — структурированная реализация: контекст → план → код.

7. **`/code-review`** — двухосный ревью перед коммитом.

8. **`/commits`** — коммит с правильным форматом.

### Расширенный конвейер
**Крупная задача: 3+ дней, несколько модулей, неочевидная архитектура.**

```
/wayfinder → /grill-with-docs → /to-spec → /to-tickets → /research → /prototype → /task-check → /implement → /code-review → /commits
```

Начните с `/wayfinder` для карты решений, затем следуйте основному потоку по тикетам.

## Стендалоны

| Ситуация | Скилл |
|----------|-------|
| Не знаю, что делать | `/ask-junie` (этот скилл) |
| Баг | `/diagnosing-bugs` |
| Новая сессия или продолжить | `/session-check` |
| Аудит проекта | `/audit [тип]` |
| Синхронизация отчётов аудитов | `/audit-sync` |
| Конфликты между отчётами | `/audit-conflicts` |
| Планирование крупной задачи | `/wayfinder` |
| Прототип UI | `/prototype` |
| Исследование | `/research` |
| Доменная модель | `/domain-modeling` |
| Обучение новому навыку | `/teach` |
| Коммиты и ветки | `/commits` |

## Как использовать

Опишите ситуацию, и AI подскажет воркфлоу:

**Пример 1 — мгновенная правка:**
```
/ask-junie
Измени текст кнопки «Сохранить» на «Отправить»
```
→ AI: «Мгновенная правка — просто скажите Junie изменить текст. Без скиллов.»

**Пример 2 — простая задача:**
```
/ask-junie
Добавить валидацию отрицательных цен
```
→ AI: «Простой режим: `/task-check` → `/implement` → `/code-review`. Решение ясно, но затронет 2-3 файла.»

**Пример 3 — средняя фича:**
```
/ask-junie
Я хочу добавить админку цен, но не уверен, с чего начать
```
→ AI: «Основной поток: `/grill-with-docs` уточнит задачу, затем `/to-spec` → `/task-check` → `/implement` → `/code-review`.»

**Пример 4 — крупная задача:**
```
/ask-junie
Нужно интегрировать IFC-парсер для серверного рендеринга
```
→ AI: «Расширенный конвейер: начните с `/wayfinder` для карты решений, затем `/grill-with-docs` → `/to-spec` → `/to-tickets` → по тикетам.»
