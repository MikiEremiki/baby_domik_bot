# To Spec

Этот скилл берёт контекст текущего разговора и понимание кодовой базы и создаёт спецификацию. НЕ опрашивайте пользователя — просто синтезируйте то, что вы уже знаете.

## Процесс

1. Изучите репозиторий, чтобы понять текущее состояние кодовой базы. Используйте терминологию из `docs/GLOSSARY.md` и учитывайте ADR.

2. Опишите швы (seams), на которых вы будете тестировать фичу. Существующие швы предпочтительнее новых.

3. Напишите спецификацию по шаблону ниже и сохраните в `.scratch/SPEC.md`.

## Шаблон спецификации

```markdown
# Спецификация: <название>

## Проблема

Описание проблемы, которую решает фича.

## Поведение

Что должно работать после реализации. Use cases, acceptance criteria.

## Дизайн кода

- Затронутые файлы и модули
- Швы (seams) для тестирования
- Изменения API (если есть)

## Миграция

Изменения данных, backward compatibility, rollout план.

## Доказательства

Как мы узнаем, что фича работает: тесты, ручная проверка, метрики.
```

## Важно

- Спецификация — это документ о решениях, не черновик
- Используйте термины из `docs/GLOSSARY.md`
- Учитывайте ADR из `docs/ADR.md`
- Сохраняйте в `.scratch/SPEC.md` (git-ignored, удаляется после реализации)
