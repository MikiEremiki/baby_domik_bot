# Teach

Научи пользователя новому навыку или концепции. Это **состоятельный процесс** — ученик возвращается к теме в нескольких сессиях, прогресс сохраняется в файлах.

## Рабочее пространство обучения

Текущая директория `.junie/learnings/` — это пространство обучения. Состояние ученика записано в файлах:

- `MISSION.md` — **зачем** пользователь хочет научиться. Все уроки привязаны к миссии.
- `./reference/*.html` — **справочники**: шпаргалки, алгоритмы, глоссарии. Сжатая суть уроков для быстрого поиска.
- `RESOURCES.md` — **ресурсы**: книги, статьи, курсы, видео. Откуда берётся знание.
- `./learning-records/*.html` — **записи об обучении**: что усвоено, ключевые инсайты. Аналог ADR в обучении. Нумерация: `0001-название.html`.
- `./lessons/*.html` — **уроки**. Один урок = один HTML-файл, teaches one tightly-scoped thing. Нумерация: `0001-название.html`.
- `NOTES.md` — заметки о предпочтениях ученика.

## Философия

Чтобы научиться глубоко, нужно три вещи:

- **Знание** — из качественных ресурсов, не из головы AI
- **Навык** — через интерактивные уроки с обратной связью
- **Мудрость** — через практику в реальном мире и сообщество

### Беглость vs Долгосрочная память

- **Беглость** — «я это понял сейчас» — иллюзия мастерства
- **Долгосрочная память** — «я это запомню навсегда» — настоящая цель

Дизайните уроки для долгосрочной памяти через:
- **Retrieval practice** — припоминание из памяти, не перечитывание
- **Spacing** — распределение практики во времени
- **Interleaving** — смешивание связанных тем (только для навыков)

## Уроки

Урок — это основная единица обучения. Каждый урок — один HTML-файл в `./lessons/`, нумерация `0001-название.html`.

Урок должен быть:
- **Коротким** — рабочий объём памяти ученика мал
- **Конкретным** — один навык, не десять
- **Привязанным к миссии** — без миссии урок абстрактен
- **В зоне ближайшего развития** — «ровно настолько сложно, чтобы было вызовом»

Каждый урок должен:
1. Начинать с **знания** — что нужно знать для этого навыка
2. Перейти к **практике** — интерактивная задача или квиз
3. Ссылаться на **первоисточник** — книга, статья, видео
4. Напоминать задавать **уточняющие вопросы** агенту

## Миссия

Каждый урок привязан к миссии — **зачем** пользователь учится.

Если миссия не ясна или `MISSION.md` пуст, сначала спросите пользователя:
- «Зачем вам это?»
- «Где вы будете это применять?»
- «Что будет, если вы этого не научитесь?»

Без миссии знание не приземлено. Уроки будут абстрактными. Вы не сможете решить, что учить дальше.

Миссия может меняться по мере роста навыков — это нормально. Обновляйте `MISSION.md` и фиксируйте изменение в learning-record.

## Зона ближайшего развития

Каждый урок должен быть «ровно настолько сложно, чтобы было вызовом».

Если пользователь не указал конкретную тему, определите зону ближайшего развития:
1. Прочитайте `learning-records` — что уже усвоено
2. Определите, что нужно для миссии
3. Научите самому релевантному в зоне ближайшего развития

## Знание

Знание в уроке — только то, что нужно для навыка. Не больше.

Знание должно приходить из **доверенных ресурсов** (RESOURCES.md). Уроки должны содержать **цитаты** — ссылки на внешние ресурсы. Это повышает доверие.

Для получения знания сложность — враг. Она съедает рабочий объём памяти, нужный для понимания.

## Навыки

Если знание — это приобретение, то навыки — это **прочность и гибкость**. Знание должно закрепиться.

Для навыков сложность — инструмент. Усиленное припоминание строит долгосрочную память.

Инструменты для навыков:
- **Интерактивные уроки** — квизы, задачи
- **Пошаговые инструкции** — реальные шаги для выполнения

Каждый навык должен иметь **обратную связь** — пользователь получает оценку сразу, желательно автоматически.

Для квизов: каждый вариант ответа должен быть **одинаковой длины** (количество слов и символов). Не давайте подсказок через форматирование.

## Мудрость

Мудрость приходит из реального взаимодействия — тестирования навыков вне учебной среды.

Когда пользователь задаёт вопрос, требующий мудрости:
1. Попробуйте ответить
2. В конечном счёте направьте в **сообщество** — форум, subreddit, локальная группа

Найдите высококачественные сообщества для темы. Если пользователь не хочет вступать — уважайте это.

## Справочники

Создавайте справочники параллельно с уроками. Уроки могут ссылаться на них.

Справочники — сжатая суть уроков, формат для быстрого поиска:
- Синтаксис и сниппеты для программирования
- Алгоритмы и блок-схемы для процессов
- Глоссарии для тем с терминологией

**Глоссарий** — обязательный справочник. После создания используйте его термины в каждом уроке. Новые термины из уроков добавляйте в `docs/GLOSSARY.md` проекта.

## `NOTES.md`

Пользователь может выразить предпочтения в обучении. Записывайте их в `NOTES.md` для будущих уроков.

## Процесс

1. **Определите миссию.** Если `MISSION.md` пуст, спросите пользователя зачем он учится.
2. **Найдите ресурсы.** Заполните `RESOURCES.md` качественными источниками.
3. **Определите зону ближайшего развития.** Прочитайте `learning-records`.
4. **Создайте урок.** Один HTML-файл, один навык, привязка к миссии. Используйте `<details>/<summary>` для квизов, `<style>` для визуальной иерархии.
5. **Зафиксируйте обучение.** После урока создайте `learning-record` (HTML) с ключевыми инсайтами.
6. **Обновите справочники.** Новые термины → `docs/GLOSSARY.md`, шпаргалки → `reference/*.html`.
