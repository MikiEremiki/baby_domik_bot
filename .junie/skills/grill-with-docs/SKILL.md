# Grill with Docs

Бескомпромиссный опрос, который также фиксирует терминологию и решения в вашем репозитории. Это тот же опрос, что и `/grill-me`, но с бумажным следом: обновляет `docs/GLOSSARY.md` и создаёт ADR.

## Как это работает

1. Вы описываете идею
2. AI задаёт вопросы раундами (через `grilling`)
3. Когда термин решён → обновляется `docs/GLOSSARY.md`
4. Когда принято архитектурное решение → создаётся ADR в `docs/ADR.md`
5. Сессия завершена, когда фронтир пуст и вы достигли общего понимания

## Когда использовать

- Задача затрагивает терминологию проекта: нужно уточнить и зафиксировать
- Архитектурное решение: нужно записать ADR
- Вы работаете в рабочем каталоге проекта (не в чистом чате)

## Чем отличается от /grill-me

| | `/grill-me` | `/grill-with-docs` |
|---|---|---|
| **Файлы** | Stateless, только чат | Обновляет GLOSSARY.md и ADR |
| **Когда** | Быстрый опрос, без бумажного следа | Когда нужно зафиксировать решения |
| **Результат** | Сводка в чате | Сводка в чате + обновлённые файлы |

## Как вызвать

```
/grill-with-docs

Добавить систему абонементов в бота
```

## Результат

По завершении:
- `docs/GLOSSARY.md` обновлён новыми терминами
- `docs/ADR.md` обновлён новыми решениями (если были)
- Сводка всех решений в чате

После этого можно:
- Перейти к `/to-spec` для создания спецификации
- Или сразу приступить к реализации, если задача простая

## Важно

- Начните grill в **чистой сессии**, не поверх уже написанного плана
- Grill with docs — это stateful: он оставляет след в репозитории
