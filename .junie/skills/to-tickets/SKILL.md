# To Tickets

Разбей план, спецификацию или обсуждение на **тикеты**: вертикальные срезы (tracer-bullet), каждый с объявленными **блокировками**.

## Процесс

### 1. Собери контекст

Работай с тем, что уже в контексте разговора. Если пользователь указал путь к спецификации, прочитай её полностью.

### 2. Изучи кодбазу (опционально)

Если ещё не изучал, исследуй текущее состояние кода. Названия и описания тикетов должны использовать термины из `docs/GLOSSARY.md`.

### 3. Создай вертикальные срезы

Разбей работу на **tracer-bullet** тикеты:

- Каждый срез проходит узким, но **полным** путём через все слои (handlers, БД, NATS) — вертикально, не горизонтально
- Завершённый срез можно продемонстрировать или проверить самостоятельно
- Каждый срез помещается в одно свежее контекстное окно

Дай каждому тикету его **блокировки**: другие тикеты, которые должны завершиться перед ним.

### 4. Покажи пользователю

Предложи разбивку в виде нумерованного списка. Для каждого тикета покажи:

- **Название**: короткое описательное имя
- **Блокируется**: какие тикеты должны завершиться первыми
- **Что доставляет**: end-to-end поведение, которое этот тикет реализует

### 5. Сохрани тикеты

Сохрани одобренные тикеты в `.scratch/tickets/`:

- Один файл на тикет: `01-<slug>.md`, `02-<slug>.md` и т.д.
- Создай `PLAN.md` в `.scratch/` со ссылками на все тикеты

**Шаблон тикета:**

```markdown
# <NN>: <Название тикета>

**Что построить:** end-to-end поведение этого тикета.

**Блокируется:** номера/названия тикетов-блокировок или "Нет".

**Статус:** ready-for-agent

- [ ] Критерий приёмки 1
- [ ] Критерий приёмки 2
```

**Шаблон PLAN.md:**

```markdown
# План: <Название фичи>

Тикеты в порядке выполнения:

1. [Тикет 1](tickets/01-<slug>.md) — нет блокировок
2. [Тикет 2](tickets/02-<slug>.md) — блокируется: 1
```
