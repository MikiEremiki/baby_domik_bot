# Implement — Структурированная реализация

Сигнал «можно начинать кодить». Структурирует основной режим Junie: читает контекст, планирует изменения, реализует.

## Когда использовать

- После `/task-check` — проверка пройдена, можно кодить
- После `/to-spec` — есть спецификация, нужно реализовать
- После `/to-tickets` — есть тикет, нужно реализовать его
- В любой момент, когда задача ясна и нужно приступить к реализации

## Процесс

### 1. Собрать контекст

Определи, что уже сделано на предыдущих этапах:

- Если есть `.scratch/SPEC.md` — прочитай спецификацию
- Если есть `.scratch/tickets/` — найди следующий невыполненный тикет
- Если есть `.scratch/wayfinder-*.md` — прочитай карту пути
- Если есть описание задачи в чате — используй его

### 2. Спланируй изменения

Перед написанием кода определи:

- **Какие файлы нужно изменить** — перечисли пути
- **Что изменить в каждом файле** — краткое описание
- **Зависимости между файлами** — порядок изменений
- **Потенциальные риски** — что может сломаться

### 3. Реализуй по шагам

Выполняй изменения в порядке зависимостей:

1. Начни с файлов, от которых зависят другие
2. Для каждого файла:
   - Прочитай текущее состояние
   - Определи точные изменения
   - Примени изменения
   - Проверь, что синтаксис корректен
3. После всех изменений — краткая сводка что сделано

### 4. Проверь результат

- Убедись, что все файлы изменены корректно
- Проверь, что нет синтаксических ошибок
- Если задача затрагивает handlers/ — проверь регистрацию в `set_handlers.py`
- Если задача затрагивает БД — проверь SQLAlchemy модели и миграции
- Если задача затрагивает NATS — проверь синхронизацию publisher/consumer

### 5. Отчёт

Кратко опиши что сделано:

```
## Реализовано

- `src/handlers/reserve_hl.py` — [что изменено]
- `src/db/models.py` — [что изменено]

## Следующие шаги

- `/code-review` — двухосный ревью
- `/commits` — коммит с правильным форматом
```

## Правила

- **Не запускай `/task-check`** — это уже было сделано до `/implement`
- **Не запускай `/code-review`** — это следующий шаг после `/implement`
- **Не делай коммиты** — это делает `/commits`
- **Следуй стилю проекта** — смотри `.junie/AGENT.md` раздел 3
- **Используй `jbcontext search`** — если нужно найти код по смыслу
- **Соблюдай изоляцию сервисов** — не импортируй ptb в FastAPI, не импортируй gspread в воркеры

## Пример

```
/implement

Добавить новый админский хендлер /check_seats для проверки свободных мест
```

→ Junie:
1. Читает контекст: задача из чата, нет спеки/тикетов
2. Планирует: `src/handlers/admin_hl.py` (новый хендлер), `src/handlers/set_handlers.py` (регистрация)
3. Реализует: добавляет функцию-хендлер с фильтром admin, регистрирует в set_handlers
4. Проверяет: синтаксис корректен, фильтр admin работает
5. Отчёт: «Изменены 2 файла. Следующий шаг: /code-review»
