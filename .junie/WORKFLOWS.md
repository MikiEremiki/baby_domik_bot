# Рабочие воркфлоу

Памятка по основным процессам разработки с AI-агентом Junie.

---

## Основной воркфлоу

**Для большинства задач:** мелкие правки, средние фичи, баги.

```
Идея → /grill-with-docs → /to-spec → /task-check → /implement → /code-review → /commits
```

| Шаг | Команда | Что делает | Когда |
|-----|---------|-----------|-------|
| 1. Не знаешь, что делать | `/ask-junie` | Подсказывает, какой скилл использовать | В начале |
| 2. Задача неоднозначна | `/grill-with-docs` | AI задаёт уточняющие вопросы, обновляет `docs/GLOSSARY.md` и ADR | Если задача неочевидна |
| 3. Спецификация | `/to-spec` | Превращает обсуждение в `.scratch/SPEC.md` | После grill |
| 4. Проверка задачи | `/task-check` | Проверяет DRY, edge-кейсы, регрессии | Перед кодом |
| 5. Реализация | `/implement` | Читает контекст, планирует, пишет код | После проверки |
| 6. Ревью | `/code-review` | Двухосный ревью: стандарты + спецификация | После кода |
| 7. Коммит | `/commits` | Коммит в формате Conventional Commits + Co-authored-by | После ревью |

**Спецсценарии:**

| Ситуация | Команда |
|----------|---------|
| Баг | `/diagnosing-bugs` |
| Новая сессия? | `/session-check` |
| Аудит проекта | `/audit [тип]` |
| Синхронизация отчётов | `/audit-sync` |

## Расширенный воркфлоу

**Для крупных задач:** 3+ дней, несколько модулей, неочевидная архитектура.

```
Идея → /wayfinder → /grill-with-docs → /to-spec → /to-tickets → /research → /prototype → /task-check → /implement → /code-review → /commits
```

| Шаг | Команда | Что делает | Файл |
|-----|---------|-----------|------|
| 0. Крупная задача? | `/wayfinder` | Карта решений с туманом войны | `.scratch/wayfinder-*.md` |
| 1. Не знаешь, что делать | `/ask-junie` | Подсказывает, какой скилл использовать | — |
| 2. Уточнить задачу | `/grill-with-docs` | AI задаёт вопросы, обновляет GLOSSARY + ADR | `docs/GLOSSARY.md`, `docs/ADR-*.md` |
| 3. Спецификация | `/to-spec` | Обсуждение → `.scratch/SPEC.md` | `.scratch/SPEC.md` |
| 4. Декомпозиция | `/to-tickets` | SPEC → тикеты с блокировками | `.scratch/tickets/*.md`, `.scratch/PLAN.md` |
| 5. Исследование | `/research` | Изучение по первичным источникам | `.scratch/research-*.md` |
| 6. Прототип | `/prototype` | Прототип интерфейса или логики | `.scratch/prototype-*.md` |
| 7. Проверка задачи | `/task-check` | DRY, edge-кейсы, регрессии | `reports/YYYY-MM-DD-*.md` |
| 8. Реализация тикета | `/implement` | Читает тикет, планирует, пишет код | — |
| 9. Ревью | `/code-review` | Двухосный ревью: стандарты + спецификация | — |
| 10. Коммит | `/commits` | Conventional Commits + Co-authored-by | — |

**После реализации всех тикетов:**

- Удалить `.scratch/` — временные артефакты умирают с фичей
- Оставить `docs/GLOSSARY.md` и `docs/ADR-*.md` — постоянные артефакты

## Обучение

**Для изучения новой темы:** технология, паттерн, доменная область.

```
Тема → /teach → Миссия → Ресурсы → Урок 1 → Урок 2 → ... → docs/GLOSSARY.md
```

| Шаг | Команда | Что делает | Файл |
|-----|---------|-----------|------|
| 1. Начать обучение | `/teach` | AI становится учителем | `.junie/learnings/` |
| 2. Миссия | AI спрашивает | Зачем учитесь? | `.junie/learnings/MISSION.md` |
| 3. Ресурсы | AI находит | Книги, статьи, курсы | `.junie/learnings/RESOURCES.md` |
| 4. Урок | AI создаёт | Урок с примерами и квизами | `.junie/learnings/lessons/` |
| 5. Прогресс | AI фиксирует | Что усвоено | `.junie/learnings/learning-records/` |
| 6. Термины | AI обновляет | Новые термины → GLOSSARY | `docs/GLOSSARY.md` |

## Управление сессиями

| Правило | Почему |
|---------|--------|
| Одна сессия — одна задача | Контекстное окно ~100-200к токенов |
| План в файле, не в чате | Выживает после `/clear` |
| Progressive disclosure | Агент сам ищет информацию, не грузит всё сразу |
| Нет надежды на автокомпакцию | Сжатие контекста: 85.7% → 63.7% качества |

**Когда новая сессия:**

| Ситуация | Действие |
|----------|---------|
| Новая область кода | Новая сессия |
| Баг в другой части проекта | Новая сессия |
| Продолжение работы с handlers/ | Та же сессия |
| `/task-check` рекомендует | Следуй рекомендации |

Команда `/session-check` поможет решить.

## Мгновенные правки

**Для тривиальных изменений:** 1 файл, очевидное решение, нет риска сломать.

| Пример | Что делаете |
|--------|------------|
| Изменить текст кнопки в боте | Просто пишете в чат: "Измени текст кнопки «Выбрать дату» на «Выбрать сеанс»" |
| Исправить опечатку в сообщении | "Исправь «расчет» на «расчёт» в сообщении о бронировании" |
| Добавить комментарий | "Добавь комментарий к функции create_param_payment" |
| Переименовать переменную | "Переименуй `usr` в `user` в reserve_hl.py" |

**Правило:** если задача затрагивает **1 файл** и решение **очевидно** — просто скажите Junie. Никаких скиллов.

## Простой режим

**Для задач, где решение понятно, но нужна проверка:** 2-3 файла, очевидная логика, нет неоднозначности.

```
/task-check → /implement → /code-review
```

| Пример | Почему простой режим |
|--------|-------------------|
| Добавить валидацию поля | Решение ясно, но затронет schema + handler + возможно API |
| Поправить формулу расчёта цены | Логика понятна, но нужно проверить edge-кейсы |
| Добавить новый админский хендлер | Паттерн ясен, но нужно проверить DRY и регрессии |
| Изменить структуру клавиатуры | Понятно что менять, но нужно проверить все места использования |

**Отличие от мгновенных правок:** затрагивает 2+ файла или есть риск сломать.
**Отличие от основного воркфлоу:** нет grill (задача однозначна) и нет spec (решение ясно).

**Цепочка:**
| Шаг | Команда | Что делает |
|-----|---------|-----------|
| 1. Проверка | `/task-check` | DRY, edge-кейсы, регрессии |
| 2. Реализация | `/implement` | Контекст → план → код |
| 3. Ревью | `/code-review` | Стандарты + соответствие задаче |

**Когда НЕ простой режим:**
- 1 файл + очевидно → **Мгновенные правки** (без скиллов)
- Задача неоднозначна → **Основной воркфлоу** (с `/grill-with-docs`)
- 3+ дней, несколько модулей → **Расширенный воркфлоу** (с `/wayfinder`)

## Быстрый выбор воркфлоу

| Задача | Воркфлоу |
|--------|---------|
| Мгновенная правка (1 файл, очевидно) | **Просто скажите Junie** — без скиллов |
| Простая задача (2-3 файла, решение ясно) | `/task-check` → `/implement` → `/code-review` |
| Исправить баг | `/diagnosing-bugs` → `/implement` → `/code-review` |
| Мелкая правка (1-2 файла) | `/task-check` → `/implement` → `/code-review` |
| Средняя фича (3-5 файлов) | `/grill-with-docs` → `/to-spec` → `/task-check` → `/implement` → `/code-review` |
| Крупная задача (неделя+) | `/wayfinder` → `/grill-with-docs` → `/to-spec` → `/to-tickets` → по тикетам |
| UI-дизайн | `/prototype` → `/to-spec` → `/implement` |
| Изучить новую тему | `/teach` |
| Аудит проекта | `/audit [тип]` |
| Не знаешь, что делать | `/ask-junie` |
